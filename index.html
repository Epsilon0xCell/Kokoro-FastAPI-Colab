Kokoro-FastAPI-Colab: The Launch Console

One Colab notebook, four cells, that stands up a Kokoro text-to-speech API on a T4 GPU and gives it a public address.

What this is

I keep a text-to-speech voice on call for the chat clients I use, and renting a GPU by the month for it makes no sense. This notebook is my answer: open it in Google Colab, pick the T4 GPU runtime, put in an ngrok token, run one cell, and a Kokoro TTS server is up with a public URL I can paste into SillyTavern or anything else that speaks the OpenAI audio endpoints.

The server itself is not mine. The launcher clones remsky's Kokoro-FastAPI and starts its GPU script. What I wrote is everything around that: the install steps, the model download into the folder the start script expects, the background server thread, the two ways the launcher decides the API is ready, the speech test that saves a real audio file, and the ngrok tunnel with its fallback. An earlier version of the README said the tunnel was Cloudflare. It is ngrok, it always was in the code, and the README has been corrected to say so.

The run, in the order the cell runs it

1Config first, in the cell itself

Two values sit at the top of the launcher cell: the ngrok auth token, which is required, and a custom domain, which is optional. There is no settings file and no widget. You edit the cell, which is the honest interface for a notebook people copy and rerun.

2Clients installed, then the system pieces

The cell installs requests, loguru, and pyngrok with pip, then espeak-ng from apt, because that one is a system binary the server needs on the machine, and uv because the setup steps that follow call it.

3A fresh clone and the model

Any old clone is deleted first, because Colab cells get rerun in the same working directory and cloning into a leftover folder either fails or mixes two checkouts. Then the launcher clones Kokoro-FastAPI and downloads the model into the v1_0 folder inside it, which is the layout the start script looks for.

5The wait: two signals, neither trusted alone

I judge readiness two ways. The log reader can say ready, and the wait also polls the voices endpoint once a second for up to 180 attempts. The endpoint can answer before the model has finished loading, and log lines can lag when output is buffered, so one signal by itself would lie to me in both directions.

If the budget runs out but the process is still alive, the wait tries once more with a longer timeout and then asks the person watching whether to continue. A slow load on a T4 is normal, and my timer is a deadline I picked, not proof that anything died.

6A real speech test before any tunnel

The local address is tested before the tunnel opens, so a failure tells me which half broke. The test is a real speech request, not only the voices list, because an endpoint can list voices while synthesis itself is still broken. The returned audio is saved to test_output.mp3 as proof I can play.

7The tunnel, with a fallback and a guard

Before ngrok is touched, the launcher checks the token against the placeholder text an unedited copy of the notebook still holds, and stops with a plain message if it matches. A missing token should fail there, in my words, not deeper down as a pyngrok traceback. Then it tries the reserved domain first and falls back to a standard ngrok URL in the same attempt, because a reserved domain can be taken or not active yet, and a working plain URL beats a failed setup.

8The loop at the end is the point

When the tunnel is up, the cell sleeps and prints a status line every minute, on purpose. A finished Colab cell lets the runtime be reclaimed, and a reclaimed runtime takes the server, the tunnel, and the public URL down with it. The notebook stays alive until I interrupt the cell myself.

What I am not claiming

Not run live by me in the last check. The notebook file was opened and read cell by cell, and it parses as valid JSON. A live run needs a Google Colab session with a T4 GPU and a real ngrok token, and neither was used for the check, so GPU start-up, the model download, and tunnel creation are true as coded, not as observed.

The keep-alive snippet is unverified against the current Colab interface. It is printed above exactly as the notebook carries it.

The token stays yours. Nothing on this page shows a token value, and the notebook ships with placeholder text in that spot on purpose, with the guard described at stage 7 rejecting it.

Getting your own ngrok pieces

The notebook's last cell is the full guide. Short version:

  1. Create a free ngrok account and verify the email if it asks.
  2. In the ngrok dashboard, open the Auth section and copy your auth token.
  3. Optionally reserve a domain in the dashboard's Domains section, so the tunnel gets the same address every run.
  4. Set NGROK_AUTH_TOKEN in the launcher cell, set NGROK_CUSTOM_DOMAIN if you reserved one, pick the T4 GPU runtime, and run the cell.
